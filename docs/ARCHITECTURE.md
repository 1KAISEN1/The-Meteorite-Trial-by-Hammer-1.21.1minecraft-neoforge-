## 0. 产品定位

本模组是 Minecraft 1.21.1 / NeoForge 的 Create 附属。

核心玩法是**自由锻刀**。

| 关键词 | 权重 |
| --- | --- |
| 自由锻刀 | 主轴 |
| 材料与合金 | 次要玩法 |
| Create 自动化 | 辅助工具 |
| 像素画风 | 硬约束 |

---

## 1. 一把刀的生命周期

下表列出七个阶段。第 2、3、4 阶段是手工核心。

| 阶段 | 玩家做什么 | 系统算什么 | 机器能辅助吗 |
| --- | --- | --- | --- |
| 0 备料 | 选陨铁，决定掺什么 | 合金比例 → 材料属性 | 否 |
| 1 熔炼 | 投料、控温、出坯 | 坯料尺寸与成分 | 是 |
| 2 锻打 | 加热、锤击、回炉 | 形变、温度、硬化 | 是 |
| 3 热处理 | 淬火、回火 | 硬度与韧性 | 是 |
| 4 精加工 | 打磨、开刃 | 刃角 → 锋利度 | 是 |
| 5 装配 | 铸造配件、雕刻 | 配重、握持 | 是 |
| 6 附魔 | 选咒语组合 | 共鸣 → 效果 | 部分 |
| 7 使用 | 战斗、维护 | 磨合度、磨损 | — |

机器只减轻重复劳动。机器不替代创作。

**自动锻刀不提供模板。** 它只能重放玩家自己的锤击记录。

## 2. 形态模型

刀的形状用**粒子云**表示，不用体素网格。

```
形态 = 粒子位置 + 形变梯度 F + 塑性形变 Fp
```

- 粒子数：20000。
- 粒子不随机分布。用确定性哈希打散。
- 弯曲是粒子位置的直接结果。不需要单独存中线曲线。

**厚度是隐藏维度。** 渲染时用明暗表现。

---

## 3. 锻造场景与几何

铁砧竖立。刀坯板面正对玩家。

| 屏幕维度 | 对应 |
| --- | --- |
| X | 刀身长度 |
| Y | 刃 ↔ 背 |
| 深度 | 厚度（不可见） |

两条核心规则：

1. **锤击 = 局部厚度减小 + 被排开的体积向四周流动。**
2. **轮廓 = 粒子云的实际边界。**

---

## 4. 温度

- 内部用**绝对摄氏度**。
- 可锻区间是 `[0.6·Tm, 0.95·Tm]`。`Tm` 是熔点。
- 颜色 = 黑体辐射色(温度) + 材料色调偏移。
- 升温速度取决于热源功率与材料热容。
- **手工锤没有刻度滑条。** 系统确定，玩家看不到数值。

## 5. 材料与合金

### 5.1 主体层级

主体按强度分六层。

| 层 | 主体 | 说明 |
| --- | --- | --- |
| 1 | 铜 | 最软 |
| 2 | 铜合金 | 青铜、黄铜 |
| 3 | 铁 | |
| 4 | 钢 | 铁加碳。碳比例可变 |
| 5 | 普通钢合金 | 钢加铬、镍、钨、钛、铝 |
| 6 | 神话钢合金 | 钢加山铜、秘银 |

**一切其他金属都是合金材料。** 包括下界合金、锌、锡、铅、银、金。

### 5.2 材料参数

每种材料有六组参数：

```
熔点、再结晶温度、硬度（屈服）、韧性、硬化系数、导热
```

- 钢不是一种材料。它是一个区间。
- 碳越高，硬度越高，韧性越低，熔点越低。
- **脆性 = 硬度 ÷ 韧性。** 脆性是派生量，不是独立参数。

### 5.3 合金规则

- 合金参数 = 各组分**质量加权平均**。
- 配比以**流体**为准。精度 25 mB。
- 固体只是来源。
- 配比界面必须实时预览熔点、热容、色调。

## 6. 工件范围

### 6.1 beta 阶段

| 工件 | 自由度 | 说明 |
| --- | --- | --- |
| 剑 | 完全自由 | 粒子塑形 |
| 工具 | 半自由 | 头部形状可调，限制在模板区域内 |
| 盔甲 | — | 不锻造。用普通合成 |

### 6.2 实现顺序

剑 → 工具 → 盔甲。

### 6.3 盔甲延期

- beta 前：用合成，不接粒子系统。
- beta 后：单独设计粒子模板。
- 见 D-040。

剑和工具共用同一套粒子系统。只是模板不同。

## 7. 附魔：三层结构

| 层 | 内容 | 获得方式 |
| --- | --- | --- |
| 主附魔 | 材料共鸣的机制性效果 | 打造时由合金决定 |
| 附属附魔 | 反击等 | 待定 |
| 磨合度 | 使用中成长 | 使用积累 |

- 天外因子以**属性赋予**方式参与。
- 共鸣范围是**整把剑**。
- 触发只有三种：击中、格挡、蓄力。
- 效果是机制性的。它改变打法，不是纯数值。

---

## 8. 格挡

- **持续举剑。** 没有时机判定。
- 免伤 75% 或 100%。
- 铸造质量影响耐久消耗。
- 反击来自附属附魔或高磨合度。
- 无剑格：更轻更灵活，但反击更难获得。

---

## 9. 核心承诺：剑可以带一辈子

- **耐久不会造成永久性损伤。**
- 剑不会因使用而永久变差，也不会消失。
- 磨损是状态。钝了可以打磨，卷刃了可以回火。
- 目标：让剑成为有历史、有情感的陪伴物，不是消耗品。
- 这与原版耐久机制明确分歧。

---

## 10. 磨合度

- 绑在剑上。换剑成本高。
- 只对**击杀**与有效维护增长。不看命中。
- 分档解锁回报。
- 重铸不涨磨合度。
- 目标：让玩家一条路走到黑。

---

## 11. 重铸

- 保留形状、磨合度、附魔。
- 成本高于重打。
- 要求手柄、重心、长度完全一致。
- 定位：无痕更换材质。

---

## 12. 石中剑

- 死亡时（非掉落），剑变成插在石头里的"石中剑"。
- 找回依赖整合包的地图死亡点标记。
- 未来与道家咒术模组联动。

---

## 13. 世界生成

- **程序化陨石坑。** 黑曜石球加陨铁矿。
- 坑壁玻璃化。周围散落碎片。
- 坑中心约产 32 锭。陨石沙一组约洗出 3 锭。
- 周边转为"陨石沙漠"生物群系。
- 结构最远间隔不超过 700 格。
- 只生成在开阔地形：平原、向日葵平原、沙漠、稀树草原。

---

## 14. 工具与观测

- **锻造锤（动力锤）：** 专用。需要黄铜。可精确控制力度与速度。
- **手工锤：** 无刻度滑条。
- **铁匠眼镜：** 显示重心、局部厚度、质量分布、手感评级。
- **配重：** 由剑首与剑格调节。UI 支持反算配件重量。

---

## 15. 属性映射

| 属性 | 主要由谁决定 | 大白话 |
| --- | --- | --- |
| 软伤 | 刃角 + 刀身宽度 | 切轻甲、切肉 |
| 硬伤 | 质量 + 刃角 | 砸重甲、劈骨头 |
| 破甲 | 刃角 + 质量 | 能劈开多硬的甲 |
| 攻速 | 转动惯量 | 越难转越慢 |
| 耐久 | 最薄处厚度 + 材料韧性 | 最薄的地方先坏 |
| 攻击距离 | 总长度 | 越长越够得着 |
| 击退 | 质量 + 重心靠前 | 沉的东西推得远 |

- **重量不是独立属性。** 它通过转动惯量影响攻速。
- **显示模式：** 默认评级（S/A/B/C）。戴铁匠眼镜显示精确数字。
- **伤害分两段：** 软伤走正常护甲计算。硬伤部分穿透护甲。

## 16. 数据模型

刀的几何从粒子云导出。

```java
BladeMetrics
├── length, width, thickness      // 包围盒
├── mass                          // 总质量
├── centerOfMass                  // 质量加权重心
├── inertia                       // 绕重心三轴转动惯量
├── sectionWidths[]               // 沿长度分段宽度
├── sectionThicknesses[]          // 沿长度分段厚度
└── minThickness                  // 最薄处
```

锻造状态：

```java
BladeState
├── temperature[]     // 每粒子温度
├── plasticStrain[]   // 每粒子累积塑性应变
├── folds             // 折叠次数。层数 = 2^folds
└── carbonContent     // 碳含量（钢专用）
```

存档只存位置和状态。形变矩阵不存。

## 17. 与 Create 的关系

- 目标：完整附属。Ponder 教学必备。
- 只用公开 API、动力学方块、配方注册。
- 不碰 Mixin 与 Create 私有实现。
- 版本必须严格配对。每次 Create 更新后重新编译验证。
- 各玩各的不等于不兼容。不依赖手搓学等附属。

---

## 18. 设计原则（硬约束）

1. **可复现。** 相同输入得到相同结果。
2. **低试错成本。** 失败产出信息，不产出损失。
3. **高容错。** 没有"一步做错整件报废"。
4. **无唯一最优解。** 靠正交的效用维度，不靠调数值。
5. **拒绝随机。** 打铁流程内零随机。
6. **不做 MITE 式压力。**

## 19. 协作方式

用户保留对每个细节的决定权。

工作方式：

```
1. 给 2–3 个可比较方案，含取舍。
2. 用户拍板。
3. 才写代码。
4. 用户验收。不满意就推翻。
5. 确认后才提交。
```

- 不"顺手做了"用户没确认的东西。
- 细节未敲定前不开工。
- 每项决策记入 `DECISIONS.md`。
- 未决问题记入 `OPEN_QUESTIONS.md`。
