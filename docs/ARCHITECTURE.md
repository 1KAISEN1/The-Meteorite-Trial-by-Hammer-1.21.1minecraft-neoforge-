# ARCHITECTURE —— 已确定的系统架构

> 只写**已经拍板**的内容。未定项见 `OPEN_QUESTIONS.md`，决策理由见 `DECISIONS.md`。
> 本文描述"系统长什么样"，不描述代码怎么写。

## 0. 产品定位

Minecraft 1.21.1 / NeoForge 的 **Create 附属**，以**自由锻刀**为核心的高自由度锻造模组。

| 关键词 | 权重 |
| --- | --- |
| 自由锻刀 | 主轴 |
| 材料 / 合金 | 次要玩法 |
| Create 自动化 | 辅助工具 |
| 像素画风 | 硬约束 |

## 1. 一把刀的生命周期

| 阶段 | 玩家在做什么 | 系统在算什么 | 机器能否辅助 |
| --- | --- | --- | --- |
| 0 备料 | 选陨铁，决定掺什么 | 合金比例 → 材料属性 | 否 |
| 1 熔炼 | 投料、控温、出坯 | 坯料尺寸与成分 | 是（鼓风机、坩埚） |
| 2 锻打 | 加热、锤击塑形、回炉 | 体积守恒的形变、温度 | 是（动力锤） |
| 3 热处理 | 淬火、回火 | 硬度 ↔ 韧性 | 是（鼓风机、温度计） |
| 4 精加工 | 打磨、开刃 | 刃角 → 锋利度 | 是（砂轮） |
| 5 装配 | 铸造剑格/剑首/剑柄、雕刻 | 配重、握持 | 是（铸造机械） |
| 6 附魔 | 选择咒语组合 | 合金共鸣 → 效果 | 部分（增幅装置） |
| 7 使用 | 带着它战斗、维护 | 磨合度、磨损 | — |

2、3、4 是手工核心，机器只减轻重复劳动，不替代创作。
**自动锻刀不提供模板，只能重放玩家自己的锤击记录。**

## 2. 形态模型

```
形态 = 轮廓（厚度 > 阈值 的区域） + 厚度场 h(s,t) + 中线曲线 c(s)
```

- `s`：沿刀身弧长；`t`：横截面位置
- 曲线坐标系，保证弯曲时网格不失真
- **刀身能弯**（弯刀、日本刀、大马士革弧）
- 厚度是隐藏维度，靠明暗表现

## 3. 锻造场景与几何

**铁砧竖立**，刀坯板面正对玩家。

| 屏幕维度 | 对应 |
| --- | --- |
| X | 刀身 `s`（长度） |
| Y | 刀身 `t`（刃 ↔ 背） |
| 深度 | **厚度（不可见）** |

- 锤击 = 局部厚度减小 + 被排开体积向四周流动
- 轮廓 = 厚度高于阈值的区域
- 明暗 = 厚度梯度（法线）经固定斜光源
- 蓄力决定压入深度

## 4. 温度

- 内部用**绝对摄氏度**
- 可锻区间上限是"亮白但不熔"
- 颜色 = 黑体辐射色(温度) [+ 可选材料色调偏移]
- 升温速度取决于热源功率与材料热容
- **手工锤无刻度滑条**：系统确定，玩家不知道数值

## 5. 材料与合金

- 参数：熔点、热容、色调、密度
- 合金参数 = 各组分**质量加权平均**
- 配比以**流体**为准（灌注枪/注液器，25 mB 精度），固体只是来源
- 配比界面必须实时预览预计熔点、热容、色调

## 6. 工件范围

### 6.1 beta 阶段（剑 + 工具）

| 工件 | 自由度 | 说明 |
| --- | --- | --- |
| **剑** | 完全自由 | 粒子塑形 |
| **工具** | 半自由 | 头部形状可调，限制在模板区域内 |
| **盔甲** | — | **不锻造**，普通合成 |

### 6.2 实现顺序

剑 → 工具 → （beta 之后）盔甲

### 6.3 盔甲（延期）

- beta 前：几个部件合成，不接粒子系统
- beta 后：单独设计粒子模板（更多粒子）
- 见 D-040

核心模型通用：剑与工具共用同一套粒子系统，只是模板不同。

## 7. 附魔：三层结构

| 层 | 内容 | 获得方式 |
| --- | --- | --- |
| 主附魔 | 材料共鸣的机制性效果 | 打造时由合金决定 |
| 附属附魔 | 反击等 | 待定 |
| 磨合度 | 使用中成长 | 使用积累 |

- 天外因子以**属性赋予**方式参与（自带未知倾向，与矿物反应）
- 共鸣范围：**整把剑**（剑身 + 剑格 + 剑首 + 剑柄）
- 触发只有三种：**击中 / 格挡 / 蓄力**
- 效果是"机制性"的（改变打法），不是纯数值

## 8. 格挡

- **持续举剑**（无时机判定）
- 免伤：75% / 100%
- 铸造质量影响耐久消耗
- 反击来自附属附魔或高磨合度
- 无剑格：更轻更灵活，但反击更难获得

## 9. 核心承诺：剑可以带一辈子

- **耐久不会造成永久性损伤**，剑不会因使用而永久变差或消失
- 磨损是状态：钝了可打磨，卷刃了可回火
- 目标：让剑成为**有历史、有情感价值的陪伴物**，而不是消耗品
- 与"Jeb 的想法"（原版耐久机制）的明确分歧

## 10. 磨合度

- 绑在剑上，换剑成本高
- 只对**击杀**与有效维护增长，不看命中
- 分档解锁回报
- 重铸不涨磨合度
- 目标：让玩家"一条路走到黑"

## 10. 重铸

- 保留形状、磨合度、附魔
- 成本高于重打
- 要求手柄、重心、长度完全一致
- 定位：无痕更换材质

## 11. 石中剑

- 死亡（非死亡不掉落）时，剑变成插在石头里的"石中剑"
- 找回依赖整合包地图的死亡点标记
- 未来与道家咒术模组联动

## 12. 世界生成

- **程序化陨石坑**：黑曜石球 + 陨铁矿，玻璃化坑壁，散落碎片
- 坑中心约产 32 锭；陨石沙一组约洗出 3 锭
- 周边转为"陨石沙漠"生物群系
- 结构最远间隔不超过 700 格
- 限定"开阔地形"（平原 / 向日葵平原 / 沙漠 / 稀树草原）

## 13. 工具与观测

- **锻造锤（动力锤）**：专用，需要黄铜，可精确控制力度与速度
- **手工锤**：无刻度滑条
- **铁匠眼镜**：显示重心、局部厚度、质量分布、手感评级
- 配重：由剑首与剑格调节，UI 支持反算配件重量

## 13.5 属性映射

| 属性 | 主要由谁决定 | 大白话 |
| --- | --- | --- |
| **软伤** | 刃角 + 刀身宽度 | 切轻甲、切肉 |
| **硬伤** | 质量 + 刃角 | 砸重甲、劈骨头 |
| **破甲** | 刃角 + 质量（独立属性） | 能劈开多硬的甲 |
| **攻速** | 转动惯量 | 越难转越慢 |
| **耐久** | 最薄处厚度 + 材料韧性 | 最薄的地方先坏 |
| **攻击距离** | 总长度 | 越长越够得着 |
| **击退** | 质量 + 重心靠前 | 沉的东西推得远 |

- **重量不作为独立属性**，通过转动惯量 → 攻速间接体现
- **显示模式**：默认评级（S/A/B/C），戴铁匠眼镜显示精确数字
- **伤害分两段**：软伤走正常护甲计算；硬伤部分穿透护甲

## 14. 数据模型

**剑的形状存为体素网格**：`64 × 32 × 6`，每格 1 字节。

```
BladeShape
├── voxels     64×32×6 字节数组
│              0 = 空，1–255 = 材料 ID
├── curve      中线曲线 c(s)（独立参数，不烘焙进体素）
└── meta       工艺信息（温度历史、磨合度、附魔等）
```

- **不存操作序列**（重放负担太大），只存最终形状
- 弯曲是独立参数，改弯曲不需要重排体素
- 渲染：沿深度投影 → 高度图 + 材料 → 法线 → 明暗 → 2D 贴图
- 属性计算：从体素直接求质量、重心、转动惯量、刃角、长度

**待定**：体素数据的压缩格式（原始 12 KB/把，必须压缩后再进 NBT）。

## 15. 与 Create 的关系

- 目标：完整附属，Ponder 教学必备
- 只用公开 API、动力学方块、配方注册
- 不碰 Mixin 与 Create 私有实现
- 版本必须严格配对，每次 Create 更新后重新编译验证
- **各玩各的不等于不兼容**：不依赖手搓学等附属

## 16. 设计原则（硬约束）

1. **可复现**：相同输入 → 相同结果
2. **低试错成本**：失败产出信息，不产出损失
3. **高容错**：无"一步做错整件报废"
4. **无唯一最优解**：靠正交的效用维度，不靠调数值
5. **拒绝随机**（打铁流程内）
6. **不做 MITE 式压力**

## 17. 协作方式

用户习惯深度定制，保留对每个细节的决定权。

工作方式：

```
① 给 2–3 个可比较方案（含取舍）
② 用户拍板
③ 才写代码
④ 用户验收，不满意就推翻
⑤ 确认后才提交
```

- 不"顺手做了"用户没确认的东西
- 细节未敲定前不开工（用户明确：讨厌屎山代码）
- 每项决策记入 `DECISIONS.md`，未决问题记入 `OPEN_QUESTIONS.md`
